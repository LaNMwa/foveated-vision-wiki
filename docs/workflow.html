先做出完整教材，
再用檢查結果改進 Graph

本次選擇 Graph 作為主要工作流程表示法。Graph 的箭頭含有失敗返回路徑，因此同時具備 Loop，不需要另外製作一套獨立 Loop。

DESIGN V1

第一版 Graph：先完成有品質的 12 頁教材

V1 包含五篇來源、12 頁完整課程、影像資料流程、各篇研究說明與總結；流程已有基本檢查點和 FAIL 回路。當時的不足是檢查只確認「來源有出現、簡報有產出」，尚無分層分類與讀者理解的品質 Gate。

ACTUAL REVIEW

檢查 V1 後，觀察到三個可改善之處

現象為何需要調整修改哪個節點
文獻已完整，仍需更精準的來源對照只確認有五篇引用，無法檢查重點敘述是否真的由相對應的原文支持Retrieve 後新增 Evidence / Coverage Gate
學理已有交代，但層級交錯初學者仍可能把 FOVEA 的軟體 Warp、RPR 的 DRAM 優化當成 Sensor 少讀Outline 後新增 Teaching Gate，先評估教學順序與案例
HTML 已可翻頁，但缺乏完整交互測試目標需要檢查小螢幕、按鍵、Source Links、交互控制，不能只看能否產生檔案Render 後新增 Browser Gate
DESIGN V2

第二版 Graph：把錯誤送回正確的地方

綠色節點：資料與發布；紫色：內容產生；黃色：品質檢查；橘色虛線：FAIL 回路。

G1 · COVERAGE

證據不夠 → 回 Wiki

如果無法指出某個重點的 Paper / Page，回到原始 PDF 或整理摘要，而不是硬寫簡報。

G2 · TEACHING

新手易混淆 → 重排大綱

如果教學無法回答「哪個階段省什麼」，增加層級圖、案例及反例，再逐頁編排。

G3 · BROWSER

功能失敗 → 修改 HTML

如果翻頁、視窗尺寸或計算不正確，修正互動程式與版面，再執行一次相同測試。
