讓智慧相機，把資源留給重要的畫面

從一張影像出發，理解 ROI、選擇性取樣、資料傳輸與 FPGA Buffer 的關係。

01 · QUESTION

高解析度影像，為什麼會變成負擔？

CAPTURE

感測與讀出

像素越多，感測端的讀取、量化及輸出有可能需要更多資源。

MEMORY

搬移與儲存

完整影格需寫入、讀取記憶體；持續錄影時會累積大量資料流量。

COMPUTE

模型推論

高解析度有助於小物體辨識，但也可能增加前處理與模型運算量。

一個高效率視覺系統，要分別觀察「感測成本、資料搬移成本、運算成本」。

02 · CONCEPT

ROI：哪些畫面值得保留更多細節？

Region of Interest

ROI 是特別需要辨識、追蹤或分析的影像區域，例如馬路上的車輛與行人。

  1. 決定要關注的位置
  2. 為 ROI 保留適當細節
  3. 對背景採用較低資料需求的策略

綠色格子＝示意 ROI；它可以是軟體處理的區域，不一定代表 Sensor 已改變實際讀取。

08 · PAPER P5

D-SWIM：面對不同影像寬度，Buffer 仍能工作

串流式影像處理常需要 Line Buffer，暫存前面幾列像素，供 2D Convolution、Corner Detection 等運算重複使用。

D-SWIM 利用可動態編程的緩衝架構，支援執行時變更影像尺寸。

11 · CLOSING

最後記住的三件事

01

ROI ≠ 必然省 Sensor

要先確認 ROI 是在 Sensor 前、Sensor 端，還是 Sensor 後處理。

02

資料量 ≠ 功耗

節省的是哪種資料移動，以及基準條件為何，都需要註明。

03

Buffer 關係到正確性

多通道與可變寬度資料，會把原本簡單的影像流變成硬體資料排列問題。
