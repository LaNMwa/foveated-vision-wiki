從 ROI 到 FPGA Buffer：影像資料到底在哪裡變少？

你看到一張「背景較模糊、車子很清楚」的影像。
這張影像的資料，是從 Sensor 就少了，還是之後才減少？

5 篇原文15 頁教學有來源與檢查
沿著資料流認識 FOVEA、VisionMode、RPR、TuMag 與 D-SWIM。
以交通場景作為貫穿教材的例子 · 原創示意圖
LEARNING GOALS

這份教學看完，你應該能回答三題

01 · WHO

哪個模組產生了資料？

辨認 Sensor、ISP、FPGA、Memory 與 AI 模型的角色。

02 · WHERE

資料在哪個位置被減少？

能分別解釋採樣、編碼、重排與緩衝，不再混為一談。

03 · WHY

如何判斷「節省」是否成立？

區分示意估算、論文測試結果與硬體實作限制。

01 · MOTIVATION

高解析度看得清楚，卻不一定最有效率

1920 × 1080 畫面共有 2,073,600 pixels。如果只有一小塊需要細看，整張高解析度處理可能造成不必要的資料負擔。

02 · SYSTEM MAP

先建立完整資料地圖：四個不能混淆的層級

A · 光電

Sensor Readout

像素曝光、ADC 量化、掃描輸出；能否選擇性輸出取決於 Sensor 架構。

B · 影像

ISP / Resampling

去馬賽克、Gamma、影像縮放或 Foveated Warp；影像可能已被讀取。

C · 搬移

SoC / DRAM

資料編碼、暫存與搬移；可降低後續記憶體流量。

D · 串流

FPGA / Buffer

多通道重新排列、FIFO、Line Buffer、Packet 化；確保時間與順序。

判讀任何一篇 ROI 研究時，先問：進入它的模組之前，完整資料是否已經產生？

04 · PAPER P2

FOVEA：讓有限的輸入畫布，留給重要的小物體

從一張已取得的影像中，透過注意力預估重要位置，再進行空間 Warp。畫布尺寸仍固定，局部則使用較密的採樣。

原始高解析度畫面
先有完整影像，估計重要位置
→
模型使用的重取樣畫布
讓重要位置佔用更多採樣格
STEP 1

估計重要區

利用資料集先驗或前一影格偵測結果取得顯著性訊息。

STEP 2

非均勻重取樣

重要位置佔用更多輸入畫布空間，其餘區域相應壓縮。

STEP 3

映回原座標

模型輸出的 Bounding Box 需要逆映射回原始影像位置。

特別提醒：FOVEA 是軟體影像重取樣策略，論文不能用來證明 Sensor 已在讀出時減少資料。

05 · PAPER P3

RPR：降低的是 Memory Traffic，不是 Sensor Readout

RPR 為不同區域分配不同空間解析度與更新率，採用 Encoder / Decoder 接在傳統像素串流之後。

商用 Sensor
標準 Raster Scan
→
Encoder
篩選 / 編碼區域
→
DRAM
較少寫入與讀出
→
Decoder
提供可用的影像格式
原文測試結果43–64%介面流量與 memory footprint 降幅；三種 workload
前端 Sensor仍掃描不是感測器端的 selective readout
這個差別會影響真正想省的成本：降低 DRAM 流量 ≠ Sensor 本身少讀 pixels。

07 · PAPER P5

D-SWIM：影像寬度變了，Line Buffer 也要跟著變

2D 卷積需要周圍像素；Line Buffer 暫存相鄰列。不同畫面寬度會改變儲存位置與讀取地址。

Dynamic Programmability

D-SWIM 使用可快速變更的控制設定，讓相同硬體處理不同影像尺寸。

<100 ns論文報告的硬體切換設定延遲

此架構解決 streaming buffer 的彈性；不等於 Sensor 的 ROI Readout 功能。

09 · WALKTHROUGH

一台相機要找出遠方的小車，會怎麼做？

1
先收集影像

Sensor 會依自身能力輸出影像資料；若要減少感測端輸出，必須有相應的 Sensor 支援。

2
辨認重要區域

例如先前偵測結果提示遠方的小車可能在畫面右側。

3
縮減後續處理

FOVEA 可調整模型輸入的採樣密度；RPR 可降低後段記憶體流量，兩者位置不同。

4
硬體確保連續資料流

若 FPGA 收到多通道或可變寬度的資料，須安排 FIFO 與 Line Buffer 的控制。

這是教學用假設情境，沒有聲稱五篇研究已被整合成單一可執行產品。

11 · MISCONCEPTIONS

三個說法，哪裡可能被誤解？

01

FOVEA 讓 Sensor 自己少讀 90% 像素。

點開檢查

不成立。FOVEA 的核心是已取得影像後的非均勻重取樣；不能把模型畫布的採樣量推回 Sensor 端。

02

RPR 降低的 Memory Traffic 就等於降低 Sensor 能耗。

點開檢查

不能直接推論。RPR 主要改善 SoC 內部的記憶體介面資料量，輸入仍是商用 Sensor 的標準 Raster Scan。

03

TuMag 輸出 ROI 變小，所以 16 個 FIFO 的寫入都同比例變少。

點開檢查

缺少根據。TuMag 的欄方向裁切由後段 image_tx 執行，需觀察流程順序才能判斷前級 FIFO 工作量。

這些例子是文獻辨析練習，不是對原論文內容的錯誤轉述。

12 · DECISION MAP

設計系統前，先問四個問題

STEP 1 · SOURCE

完整影像已經讀出嗎？

如果已讀出，後續調整主要影響下游的處理與流量。

STEP 2 · TARGET

真正要節省什麼？

可能是 Sensor 能量、DRAM 交通量、AI Input 或 Data TX。

STEP 3 · FORMAT

影像會改變尺寸或次序嗎？

確認 Pixel Packing、FIFO、Line Width 與控制位址。

STEP 4 · CHECK：檢查數據是論文實測、特定情境模擬，還是純教學公式。
